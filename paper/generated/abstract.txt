Agents built on large language models read tool outputs written for programs: most of what an API returns never informs the agent's answer, yet it is paid for at every turn. We learn, from an agent's own execution traces, which fields of each tool output it uses, and remove the rest. On five agents (three on real APIs, two on simulated servers following public OpenAPI descriptions), a projection learned from seven runs and applied to an unseen one removed 63% and 70% of tool-output tokens on two of the agents with real APIs and 12% on the third, and 69% and 77% on the simulated ones (re-serialising the JSON alone, with no field removed, already removes up to 13% and 17% respectively); in live runs with an expand tool for hidden fields, billed input tokens fell by 56% and 32%, and every run passed its gates, although a later re-check found one search volume of 180 written without a source. Learning only from tool calls, as a gateway would, missed a used field in 49% of held-out calls on the three agents with real APIs, against 4% when learning from complete traces. Replays with projected outputs, under a protocol frozen in advance, located the failures precisely: values the agent transforms before writing them, fields it uses only to reason, and, without an identifier field, agents inventing identifiers. A second pre-registered study showed that two safeguards, keeping identifying fields and recognising transformed values, removed those losses while keeping savings of 53% and 46% on those two real-API agents and 57% and 61% on the simulated ones, with one secondary measure of the editorial plan outside the raw arm's range; a post-hoc check found a fourth mechanism, translated values, not covered. We release the library, with a bilingual telemetry report and an MCP proxy that applies a reviewed projection in front of any server.
