Language-model agents read tool outputs written for programs: most of what an API returns is never visibly reused, yet it is paid for at every turn. We present tracetrim, a library that learns from an agent's own traces which fields of each tool output the agent visibly reuses and removes the rest, protecting identifiers and letting the agent recover any hidden field with an expand tool. In live runs of tracetrim 0.4 on gpt-5.6-terra, under frozen protocols, a fixed projection with expand lowered the median LLM API cost per run by 30% and 24% on two agents with every implemented gate passing, though a stricter audit found billing diagnoses less complete with trimming; when a changed task needed removed fields that the agent recovered and wrote, adaptive learning kept them from the next run in 16 of 16 cases. Offline, with today's defaults, the learned projection removed 63%, 52% and 65% of held-out tool-output tokens on three of five agents, and 40% to 56% of what a minifier and a static metadata filter fixed in advance leave there. Earlier studies explain these defaults: learned from tool calls alone, as a gateway would, the 0.1 aggressive projection missed a used field in 49% of the held-out structured calls it trims on the real-API agents, against 4% from complete traces. On tasks held out from development, judged blind, the prudent projection of tracetrim 1.3.1 did not lower answer quality on new ordinary tasks (difference +0.05, 95% interval [-0.01; +0.13] on a 0–4 scale, at a ceiling). A stress test, with tasks built around the fields it removes, found the projection's weak point: the agent reported 83.75% of the facts those fields held against 100% with complete outputs (-0.162, [-0.225; -0.098]), at no saving, and when a free-text field it had not recovered held the fact, it mostly declared the fact absent. One added rule, to check hidden fields before declaring information absent, raised that share in a new campaign from 85.1% to 92.3% (+0.072, [+0.003; +0.144]) at no extra cost; it is the skill's default from tracetrim 1.4. In a further campaign, showing the first words of hidden free-text fields on the notice after a trimmed result raised it from 91.3% to 99.5% (+0.083, [+0.046; +0.123]), at no extra cost, the default from tracetrim 1.5. With an agent of another model family nothing was lost, but the projection cost 1.67 times complete outputs per run, in more turns. The method helps most where outputs carry much the task does not use, least where the agent cites most of what it reads. The library is released for an agent's own function-calling loop, around a LangGraph tool node and as an MCP proxy for any server; it keeps learning from the agent's final answers and writes a telemetry report useful on its own.
