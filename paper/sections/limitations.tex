\section{Limitations}
\label{sec:limitations}

\begin{itemize}
\item \textbf{Validated on the development tasks only.} The tasks, prompts, gates, safeguards and default rules
were developed on the same five agents on which they are evaluated, and Studies~2 and~3 reuse them. No result has
yet been tested on tasks, agents or APIs kept apart from development: the results describe these workloads, and
validation on new ones is the main step still missing.
\item \textbf{What the checks check.} The gates, the protocols' tests and the rule-based audits added afterwards
check identifiers, links, names, keywords and some relations (a volume against its keyword, a link against the
invoice cited, a view count against its video), not every association an answer makes. The stricter post-hoc audits confirmed nearly all answers, and their
exceptions, such as a decline reason the agent never fetched, passed the gates (Section~\ref{sec:s3audit}).
\item \textbf{No independent human rating.} Answers were checked by gates and rules; where a check failed, a rule
seemed wrong or a result was unexpected, they were read one by one by the AI agents that ran the analyses, under the
author's review. No independent human rater read every answer, and no agreement between raters was measured.
\item \textbf{Small numbers of runs.} Eight live runs per case to learn, two to five replays per arm to judge
  quality. No significance test is claimed; differences inside the range of the raw arm are reported as not
  distinguishable from run-to-run variation, which in these tasks is large (in Phase C the raw arm itself
  misdiagnosed a ticket in two of three runs).
\item \textbf{One model.} All runs of Studies 1 and 2 used \texttt{gpt-5.6-terra} at default parameters. Whether other models use
  tool outputs differently, or read projected and TOON-encoded outputs differently, is untested.
\item \textbf{Replay is not a live loop.} Phases B and Study 2 replay a fixed sequence of calls up to the final
  answer; in a live loop a projected output can also change which calls come next. Phase C measured the live loop
  on two cases only.
\item \textbf{Simulated cases.} Two of the five cases use payloads we generated from public OpenAPI descriptions.
  Their shape is realistic, their content is not, and because we designed them they are reported separately.
\item \textbf{Usage is detected reuse.} Reasoning is not observable in the APIs used, so fields used only while
  reasoning are invisible (the root of the failures reported, and safeguards cover only the blind spots that are
  known); coincident values can also make a field look used. The detector's precision and recall were not measured
  against an annotated sample.
\item \textbf{Study 2 is not an independent validation.} The safeguards were designed on the Phase B failures and
  tested on the same conversations; new tasks, runs and seeds would be needed to show that they generalise.
\item \textbf{Keyword tests.} The thermometers of billing support and CI triage test for keywords and numbers; they
  accept a negated or contradictory sentence. A stricter audit of the billing diagnoses is reported beside them.
\item \textbf{Post hoc decisions.} Three measurement corrections were made after seeing data (deviations 8, 10 and
  11); each is applied to every run, and the strict test of deviation 11 is reported beside the frozen one. The
  gates' reading of projected outputs and the re-check of the Phase C volumes (deviation 13) were also fixed or added
  afterwards.
\item \textbf{What the gates cannot see.} The editorial-plan gate checks a volume only when the run's outputs give
  one for that keyword, so a volume written without a source passes it; a post-hoc re-check found one in the live
  runs (Section~\ref{sec:phasec}).
\item \textbf{Lossless part of the savings.} Every saving reported includes re-serialisation (compact JSON without
  escapes), which removes nothing; it is reported separately so that the projection is credited only with the rest.
\item \textbf{Number formats.} Usage detection in the studies matched numbers written plainly or with dot thousands
  separators; numbers written with comma separators would have gone unseen. In all Phase A runs the agents wrote
  \CommaNumbersWritten{} such numbers, so no use was missed this way; the library matches them since version 0.3.4.
\item \textbf{Study 3.} Trimming and adaptive learning were measured on one model, \texttt{\SthreeModelA}, the strategy text on two; other
  models may organise calls, call \texttt{expand} or reword values differently. Runs are few: \SthreeRunsPerArmEOne{} per arm in E1;
  in E2 \SthreeETwoSeqPerArmSim{} sequences per arm on the simulated case and \SthreeETwoSeqPerArmReal{} on the
  real-API case, a single trajectory per arm; \SthreeEThreeRunsPerArmMin{} to \SthreeEThreeRunsPerArmMax{} per arm
  in E3, with one task per case and no trimming, so the strategy combined with trimming was not
  measured on the second model. In E3 the editorial plan and the content-gap analysis ran on recorded outputs,
  mostly the nearest recorded call rather than the same one, so only the organisation of calls is evaluated there.
  The gates and the test of E2's added requirement look for identifiers, links, names and keywords; the full
  associations and the billing audit were checked only after the results, by rules, with the cases those rules got
  wrong read one by one. The audit that \texttt{protocol-v04.md} required for billing support was run after the results,
  a deviation. Only the function-calling adapter was exercised. The offline analyses, the baselines among them, use
  the traces on which the method was developed and say nothing about live answers; apart from the baselines, whose
  rules were fixed before any number, they and the post-hoc analysis of E3 were not in a protocol, and the host
  checks are few observations per host. Every attempt is kept in every figure, the run that asked a question instead
  of doing the task included; a ratio that such a run cannot have is computed without it and says so.
\item \textbf{Third-party data.} Search results and parsed pages cannot be redistributed: for the two cases built
  on them, the released data are derived per-call records: enough to recompute which fields each call used and the
  misses, but neither the token savings, which need the payloads, nor a replay of the conversations.
\end{itemize}
